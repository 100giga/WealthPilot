# Synthetic MSME Loan-Underwriting Dataset

Synthetic data for an agentic MSME loan-underwriting platform in India.
Each part of the dataset feeds one part of the system: structured
borrower data for the tool-using agents, relationship-manager notes for
memory, a policy corpus for hybrid RAG, decisions with human-in-the-loop
outcomes for the LangGraph workflow, and labelled compliance cases for the
multi-agent compliance team.

**Everything here is synthetic.** PAN, GSTIN (with a valid checksum),
Udyam, CIN and CKYC numbers are format-valid but randomly generated, and
names are random combinations. They do not identify real people or
businesses, and must never be used for lookups against live systems. The
policy documents are illustrative, not any lender's or regulator's actual
text.

```bash
python scripts/generate_msme_data.py                     # 500 applicants, seed 2026
python scripts/generate_msme_data.py --n 5000 --seed 7   # larger or alternative draw
```

The generator uses only the standard library and is deterministic for a
given seed and size. Its output goes to `generated/`.

## Layout

```
policies/            RAG corpus: 10 policy/product notes + 1 planted injection
rag_golden_set.json  15 retrieval questions → expected policy documents
generated/           tables, memory notes, eval sets (regenerated by the script)
```

## Tables (`generated/`)

Monetary values are integer rupees. Dates are ISO 8601. Everything joins
on `applicant_id`, or on `application_id` for loan-level tables. Each
applicant has one application.

| File | Grain | What it is for |
|---|---|---|
| `applicants.csv` | applicant | Entity profile: constitution, sector/NIC, state, vintage, Udyam category vs **derived** category, `women_led` (scheme eligibility and fairness audits only) |
| `promoters.csv` | promoter | Promoters/partners/directors with DOB, PAN, shareholding and bureau score; screened against the watchlists |
| `loan_applications.csv` | application | Product (Cash Credit, Term Loan, Equipment Finance, PMMY Mudra, TReDS), amount, tenure, collateral, CGTMSE request, channel, Account Aggregator consent ID |
| `financial_statements.csv` | applicant × fiscal year | P&L and balance sheet for up to 3 FYs (fewer for young firms); the latest FY may be `provisional` |
| `bank_statement_monthly.csv` | applicant × month | 12 months before application: credits/debits, average balance, bounces, cash-deposit %, related-party credit %, OD utilisation, AA vs PDF source |
| `gst_returns_monthly.csv` | applicant × month | GSTR-3B: filing status, days late, taxable turnover (none for non-GST-registered micros) |
| `bureau_reports.csv` | promoter / entity | Individual score (or new-to-credit), CMR rank, max DPD, enquiries, written-off, suit filed, wilful defaulter |
| `kyc_records.csv` | applicant | CKYC, KYC mode, AML risk, re-KYC due date and status, beneficial-owner declaration |
| `watchlist.csv` | entry | Synthetic sanctions / PEP / wilful-defaulter list, with transliteration aliases |
| `related_parties.csv` | entry | The lender's directors, officers and their relatives (connected-lending checks) |
| `underwriting_decisions.csv` | application | Rules-engine output: DSCR, ISCR, current ratio, TOL/TNW, GST↔bank and financials↔GST variance, scorecard, grade, recommendation, reason codes, conditions, rate, HITL flags, **and** the final human decision, approver and override reason |
| `loan_performance.csv` | disbursed loan | Months on book, DPD, SMA/NPA classification; `default_90dpd_12m` is set only once the 12-month window is complete |
| `ground_truth.csv` | applicant | Latent credit quality, true 12-month PD, fraud type, planted compliance case. **For evaluation only; never expose it to agents.** |
| `rm_interactions.jsonl` | note | Relationship-manager notes with extracted `facts` (see Memory below) |
| `agent_eval_cases.json` | case | Up to 12 cases per recommendation, with expected recommendation, reason codes, conditions, HITL flag and grade |
| `compliance_eval_cases.json` | case | Every flagged or planted case plus clean controls, with expected flags and action |
| `manifest.json` | — | Seed, row counts and the outcome mix |

## How the data maps to the platform

**LLM agents and tools.** Wrap the tables as tools, for example
`get_financials(applicant_id)`, `get_bank_summary`, `get_gst_returns`,
`pull_bureau`, `screen_watchlist`. `underwriting_decisions.csv` is the
deterministic reference that an agent's recommendation is scored against.

**Persistent memory.** `rm_interactions.jsonl` has 2 to 8 timestamped notes
per applicant (episodic memory), each with structured `facts` (semantic
memory). The notes are deliberately untidy:
- `employees` is restated later with a different value, so consolidation
  must keep the most recent value.
- Some notes contain risk signals that appear nowhere in the structured
  data, such as pending GST demand notices or vague circular-trading
  explanations.
- About 5% of notes mention a partial Aadhaar number shared over WhatsApp,
  to test PII handling.

**Hybrid RAG.** `policies/` uses reason codes (`FRD_GST_BANK_MISMATCH`) and
policy IDs (`CP-MSME-2026-03`), which suit BM25, alongside prose questions,
which suit dense retrieval. Two versions of the credit policy coexist:
applications dated before 1 April 2026 must be judged under the superseded
CP-MSME-2024-01, so retrieval must respect effective dates.
`applicant_upload_ca_certificate_flagged.md` carries a planted injection.
The existing `rag.security.scan` catches three of its categories but misses
the "administrator mode" phrasing and the HTML-comment exfiltration request,
which are deliberate gaps to close. With the current `HybridIndex`, the
golden set scores recall@5 0.97 and MRR@5 0.77.

**LangGraph orchestration and HITL.** `human_review_required` and
`human_review_reasons` mark the interrupt points. Six applications are
`PENDING_HUMAN_REVIEW`, which gives a live review queue. Resolved cases
show who decided (`credit_officer`, `credit_committee`,
`compliance_officer`, `fraud_risk_unit`, `board_credit_committee`) and every
override records a reason.

**Multi-agent compliance.** Planted cases include confirmed sanctions and
PEP matches (name and DOB), wilful defaulters, connected lending, and
transliteration false positives such as Mohammed/Mohd. that a compliance
officer should clear. There are also three fraud patterns
(`gst_invoice_inflation`, `circular_trading`, `financials_inflated`). Under
the 2024 policy, many of the last two are `not_detected_by_rules`, which is
a target for an LLM agent that reads bank patterns and RM notes.

## Default draw (seed 2026, 500 applicants)

- **Recommendations:** 114 approve, 71 approve with conditions, 62 refer,
  253 reject.
- **Policy versions:** 393 applications fall under CP-MSME-2024-01 and 107
  under CP-MSME-2026-03.
- **Defaults:** 1.7% of disbursed loans with a complete 12-month window
  defaulted at 90+ DPD. Only 119 loans have a complete window, so increase
  `--n` if you need a default-modelling sample.
- **Size:** about 2.4 MB in total.

Thresholds in `scripts/generate_msme_data.py` mirror
`policies/credit_policy_msme_2026.md` and the superseded 2024 policy.
Change both together. `tests/test_msme_synthetic_data.py` checks that the
generator is deterministic, that tables join correctly, that decisions obey
the policy rules, and that the corpus is retrievable.
